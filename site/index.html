Some notes on the terminal and colour

I've been thinking about why some colour schemes are easier to read than others, and it turns out a lot of it comes down to contrast you never notice.

Here are a few things I learned while fiddling with mine this week.

Made for reading, not skimming a feed

Articles open in a quiet serif reading view, sanitised and free of tracking scripts. Work through a list without touching the mouse, and switch single-key shortcuts off if they get in the way of speech input or a screen reader.

Install it to your phone's Home Screen and the app icon shows your unread count.

A polite poller

The worker sends ETag and If-Modified-Since on every check, so an unchanged feed costs the publisher almost nothing. A feed that keeps failing backs off on its own, up to an hour between tries.

daringfireball.net/feeds/main304 not modified
sixcolors.com/feed3 new entries
example.org/rssretrying in 8 min

Every feed on its own terms

Check a busy site every five minutes and a monthly newsletter once a day. Keep noisy feeds out of All, Today and Unread so they only appear on their own page.

See why a feed broke

The last response status, content type and body are stored for every feed, so a failing subscription tells you what the server actually sent back.

Keep what you read

Save any article as a PDF, or download every image in a post as a ZIP. Move your subscriptions between instances with a JSON export.

Four containers and a database

A React web app, a Fastify API, a background worker and PostgreSQL. Everyone in the house can have their own account and read state. Feed fetches to private addresses are blocked by default, and you can allowlist just the hosts you trust.

# web, api, worker and postgres
$ docker compose ps
NAME       IMAGE                              STATUS
web        ghcr.io/bevanjkay/rss-boi:web      Up (healthy)
api        ghcr.io/bevanjkay/rss-boi:api      Up (healthy)
worker     ghcr.io/bevanjkay/rss-boi:worker   Up
postgres   postgres:16-alpine                 Up (healthy)

# poll an RSSHub instance on your LAN, and nothing else private
ALLOW_PRIVATE_HOSTS=192.168.86.199:1200

Install

curl -fsSLO https://raw.githubusercontent.com/bevanjkay/rss-boi/main/docker-compose.yml
curl -fsSL https://raw.githubusercontent.com/bevanjkay/rss-boi/main/.env.example -o .env
docker compose up -d

Set SESSION_SECRET and the database password in .env before the first start. Then open http://localhost:3000, name your instance and create the admin account.

Why self-hosted

A reader you run yourself can't be shut down, sold, or turned into a recommendation engine. Your subscriptions and read history live in your own PostgreSQL database.
